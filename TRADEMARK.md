The FaPost source code is licensed under the [Apache License 2.0](./LICENSE). That license covers the code — it does
not grant any right to use the FaPost name or logo. Section 6 of the Apache License is explicit about this:

> This License does not grant permission to use the trade names, trademarks, service marks, or product names of the
> Licensor.

This document describes how the FaPost marks may be used. It exists so that the code can stay freely usable while the
name still reliably identifies software that comes from this project.

## Covered Marks

- **FaPost**
- **FaPost Core**
- **Flow Automation Post**
- The FaPost logo and wordmark, in any colour or variation
- The `fapost/*` package namespace on Packagist and the `fapost-lab` organisation on GitHub

Collectively referred to below as *the Marks*.

## Uses That Need No Permission

You may do all of the following without asking:

- **Refer to the software.** "This service runs on FaPost", "we migrated our bots to FaPost Core", "a comparison of
  FaPost and other flow engines".
- **Redistribute unmodified releases** under the name FaPost, provided the code is unchanged and the
  `LICENSE`, `NOTICE`, and this file are included.
- **Describe compatibility of your own product.** "Compatible with FaPost", "FaPost integration", "built with FaPost",
  "for FaPost". The Marks must appear as a descriptive qualifier, never as the leading element of your product name:
  - Allowed: `Acme Analytics for FaPost`, `acme/fapost-analytics`
  - Not allowed: `FaPost Analytics`, `fapost/analytics`, `FaPost Pro`
- **Write about the project** — tutorials, courses, talks, blog posts, reviews, including paid ones.
- **Use the logo** to link to this repository or to the official documentation, unmodified and at its original aspect
  ratio.
- **Community activity** — user groups and meetups may use the Marks descriptively ("FaPost Berlin Meetup") as long as
  it is clear the event is community-run and not an official FaPost Lab event.

## Uses That Need Written Permission

Ask before you do any of the following:

- Distributing a **modified version** of FaPost under the FaPost name. Fork freely — the license allows it — but give
  the fork its own name. You may state factually that it is "a fork of FaPost".
- Offering a **hosted or managed service** named FaPost, or whose name incorporates the Marks.
- Using the Marks in a **company name, product name, application name, or app store listing**.
- Registering **domain names** or social media accounts containing "fapost" or a confusingly similar string.
- Publishing packages under the **`fapost/*` Packagist namespace**, or any namespace likely to be mistaken for it.
- Producing **merchandise** bearing the Marks.
- Any use that suggests **sponsorship, endorsement, affiliation, or certification** by FaPost Lab.

## General Rules

Whenever you use the Marks:

1. **Spell them correctly.** "FaPost" — one word, capital `F`, capital `P`. Not "Fapost", "FAPost", "FA Post", or
   "fapost" outside of code identifiers, package names, and URLs.
2. **Do not alter the logo.** No recolouring, stretching, rotating, cropping, or combining it with other marks into a
   composite logo.
3. **Do not use the Marks as a noun or verb.** FaPost is an adjective modifying a noun: "the FaPost platform", not
   "a FaPost" or "to FaPost a message".
4. **Do not imply endorsement.** Your use must not create the impression that FaPost Lab produced, reviewed, or
   approved your product.
5. **Do not use the Marks for anything unlawful,** or in a way that damages the reputation of the project.

## Modified Versions

If you distribute FaPost with your own changes, either:

- rename the software and remove the Marks from the user-visible surfaces (application name, admin UI branding, docs,
  package name); or
- request written permission to keep the name.

Attribution in the other direction is always fine and encouraged: "Derived from FaPost Core, https://github.com/fapost-lab/core".

## Requests and Questions

Open an issue in [fapost-lab/core](https://github.com/fapost-lab/core/issues) describing the intended use, or contact
the FaPost Lab maintainers directly. Permission, when granted, is given in writing, is specific to the described use,
and may be revoked if the use changes.
