# **Flow Nodes, Solutions, Tenant Activation — Architectural Summary**

## **Базовый принцип**

Нода принадлежит не tenant напрямую, а capability, поставляемой solution.

То есть:

- solution регистрирует node handlers глобально;
- registry платформы знает все доступные типы нод;
- tenant получает право использовать только subset нод согласно activation / billing.

---

## **Registry уровень**

Глобальный registry содержит все node handlers:

- core nodes;
- solution nodes;
- plugin nodes.

FlowEngine работает через registry и резолвит handler по:

- type
- version

Runtime не должен зависеть от tenant activation напрямую.

---

## **Tenant activation уровень**

Поверх registry нужен activation filter.

Tenant может использовать только ноды solution, которые активированы для него.

То есть builder работает не с полным registry, а с filtered descriptor list.

---

## **Builder policy**

Если solution выключен:

- новые ноды этого solution больше нельзя добавлять;
- существующие ноды остаются в flow definition;
- builder показывает node как disabled / unavailable;
- unknown node нельзя silently удалять;
- flow нельзя сохранить, пока disabled node явно не заменена.

---

## **Runtime policy**

Если flow уже содержит node solution:

и handler физически присутствует в коде,

flow может продолжать исполняться.

Это необходимо для:

- legacy flows;
- grace period;
- SaaS predictability.

---

## **Если handler отсутствует физически**

Если package удалён или handler не зарегистрирован:

runtime должен завершаться детерминированной ошибкой:

- NodeHandlerNotAvailableException
- session -> failed
- запись в flow_logs

---

## **Required descriptor metadata**

Каждая node descriptor должна содержать owner solution.

Минимально:

- type
- version
- ownerSolution
- label
- category
- schema

---

## **Почему это важно**

Это позволит:

- безопасно включать / отключать solution;
- не ломать существующие flow;
- корректно фильтровать builder;
- управлять SaaS capability model без переписывания runtime.

---

## **Итоговая модель**

Registry = глобальный execution language платформы.

Builder = tenant-aware filtered language.

Runtime = deterministic execution независимо от billing-состояния editor layer.
