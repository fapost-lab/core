## Контекст

Task 11 зафиксировал transaction boundary: `flow_sessions UPDATE + flow_logs INSERT` в одной транзакции. Task 18 реализует полный logging layer поверх этого контракта — схему, сервисы, retention.

## Зависимости

- Task 11 — FlowEngine::persistStep() существует, transaction boundary зафиксирован
- Task 12 — FlowOrchestrator, distributed lock: conflict статус логируется отсюда
- `tpetry/laravel-postgresql-enhanced` установлен

## Что реализовать

### Миграции

**flow_logs** — partitioned table по `created_at` (monthly, RANGE), через `tpetry/laravel-postgresql-enhanced`.

Колонки: `id` (ULID), `session_id` (FK → flow_sessions), `node_id`, `node_type`, `node_version` (int), `status` (enum: `executed|failed|conflict|terminal`), `source_handle` (nullable string), `state_changes` (JSONB nullable), `resolved` (JSONB nullable), `error` (JSONB nullable), `created_at`.

Создать первые 3 партиции при миграции (текущий месяц + 2 вперёд).

**analytics_events** — обычная таблица без партиций.

Колонки: `id` (ULID), `tenant_id`, `event_type` (string), `payload` (JSONB), `occurred_at` (timestamp).

Индекс по `(tenant_id, event_type, occurred_at)`.

### FlowLogWriter

```php
// app/Domains/Flow/Logging/FlowLogWriter.php
final class FlowLogWriter
{
    public function write(FlowLogEntry $entry): void;
}
```

Вызывается внутри транзакции из FlowEngine (Task 11). Принимает `FlowLogEntry` — value object. Не знает о `analytics_events`.

`FlowLogEntry` содержит: `sessionId`, `nodeId`, `nodeType`, `nodeVersion`, `status` (enum `FlowLogStatus`), `sourceHandle`, `stateChanges` (array|null), `resolved` (array|null), `error` (array|null).

**Политика записи `resolved`** — только если handler реально делал runtime resolution. Передаётся явно из handler результата, не вычисляется в writer.

**Что НЕ писать в flow_logs:**

- промежуточные state updates
- успешные lock acquire
- idempotency hits
- delay wakeup без execution

### AnalyticsWriterInterface + DatabaseAnalyticsWriter

```php
// fapost/foundation — контракт
interface AnalyticsWriterInterface
{
    public function record(AnalyticsEvent $event): void;
}

// app/Domains/Flow/Logging/DatabaseAnalyticsWriter.php
final class DatabaseAnalyticsWriter implements AnalyticsWriterInterface
{
    public function record(AnalyticsEvent $event): void;
}
```

`AnalyticsEvent` — value object: `tenantId`, `eventType` (enum `AnalyticsEventType`), `payload` (array), `occurredAt`.

`AnalyticsEventType` enum: `flow_started`, `flow_completed`, `flow_failed`, `rag_query_made`, `broadcast_sent`.

### Transaction boundary (интеграция с Task 11)

```php
// FlowEngine::persistStep() — уже существует из Task 11
DB::transaction(function () use ($session, $logEntry) {
    $session->save(); // version bump
    $this->flowLogWriter->write($logEntry);
});

DB::afterCommit(fn() => $this->analyticsWriter->record($analyticsEvent));
```

`AnalyticsWriter` вызывается через `DB::afterCommit()` — вне critical транзакции, синхронно после commit. Laravel events для analytics не используются.

### PruneFlowLogsCommand

```php
// app/Console/Commands/PruneFlowLogsCommand.php
// Signature: logs:prune-flow
```

Логика: определить партиции старше 30 дней → `DROP TABLE IF EXISTS flow_logs_{YYYY_MM}` через tpetry API. Не делает `DELETE`. Пишет в лог: сколько партиций дропнуто.

Scheduler: `->dailyAt('03:00')`. Не зависит от queue.

### CreateNextFlowLogPartitionCommand

```
Signature: logs:create-partition
```

Создаёт партицию на следующий месяц если не существует. Scheduler: `->monthlyOn(1, '00:00')`. Обеспечивает что партиция всегда есть до начала месяца.

## Что НЕ делать

- Не использовать Laravel events для analytics pipeline
- Не включать `analytics_events` в DB транзакцию с `flow_sessions`
- Не делать `DELETE` для retention — только `DROP PARTITION`
- Не логировать полный state snapshot — только `state_changes` (diff)
- Не создавать God-class `Logger` — `FlowLogWriter` и `AnalyticsWriter` разделены

## Архитектурные решения

**flow_logs пишет:** node executed, node failed, retry conflict (optimistic lock / lock miss), terminal transition.

**resolved policy:** пишется только если handler делал runtime resolution — condition, webhook payload template, send_message template. Полный state snapshot запрещён.

**AnalyticsWriter:** синхронно через `DB::afterCommit()`. Laravel events не используются — rollback-safe ordering и отсутствие скрытого listener coupling. Пишет только бизнес-события (flow_started/completed/failed, rag_query_made, broadcast_sent), не каждый node execution.

**Partitioning:** tpetry/laravel-postgresql-enhanced. analytics_events без партиций на первом этапе.

**Retention:** artisan command + scheduler, не queue — retention это infra maintenance, не должно зависеть от queue saturation.
