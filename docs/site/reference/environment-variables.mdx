`.env.example` is the authoritative list. This page covers the variables specific
to FaPost, and the Laravel ones whose value matters here.

## Application

| Variable | Default | Notes |
|---|---|---|
| `APP_NAME` | `FaPost-CORE` | |
| `APP_ENV` | `local` | `production` in a deployment |
| `APP_KEY` | *empty* | Generate with `php artisan key:generate`; never reuse across installations |
| `APP_DEBUG` | `true` | **Must be `false` in production** |
| `APP_URL` | `http://localhost` | Used to build webhook URLs; in `host` mode its scheme and port also shape the tenant links sent by mail (`https://<slug>.<TENANCY_BASE_DOMAIN>`) |

## Tenancy and webhooks

| Variable | Default | Notes |
|---|---|---|
| `TENANCY_BASE_DOMAIN` | `localhost` | Base domain tenant hosts are derived from |
| `TENANCY_RESOLUTION` | `single` | `single`: one tenant, named by `TENANT_SLUG`. `host`: the tenant is taken from the request host `<slug>.<TENANCY_BASE_DOMAIN>`, so one install serves many tenants; unknown hosts get 404, and hosts outside the base domain get 400. Needs a wildcard DNS name and certificate, `SESSION_DRIVER` other than `database`, and `SESSION_DOMAIN` unset; see [Several tenants](/self-hosting/docker-compose#several-tenants-host-mode) and the [upgrade note](/self-hosting/upgrading#moving-to-host-mode). Changing it needs the route cache rebuilt |
| `TENANCY_PROVISIONING_LEASE_SECONDS` | `900` | How long a provisioning run holds a pending tenant before another run may take it over (at least 60; the run renews it between steps). A crashed run frees the tenant after this long |
| `TENANCY_RENAME_REDIRECT_DAYS` | `30` | How long the old host of a renamed tenant redirects `GET` and `HEAD` requests to the new one (HTTP 302). `0` switches the redirect off. The old slug stays reserved for the tenant either way. Needs `TENANCY_RESOLUTION=host`; read when a tenant is renamed, so changing it does not affect redirects already issued |
| `TENANT_SLUG` | `app` | The tenant served in `single` mode; ignored in `host` mode |
| `WEBHOOK_BASE_URL` | `${APP_URL}` | The base providers will call back on |
| `WEBHOOK_INGRESS_DRIVER` | `laravel` | `laravel` or `gateway` |
| `WEBHOOK_GATEWAY_URL` | *empty* | Required when the driver is `gateway` |

In `host` mode `WEBHOOK_BASE_URL` and the gateway host must sit under
`TENANCY_BASE_DOMAIN`: the application answers no other host.

The Compose file also reads `CADDY_IMAGE` (a Caddy build with your DNS provider's
module) and `CADDY_SITES_DIR` (extra Caddy sites, `./caddy.d` by default); neither is
read by the application.

<Note>
  `WEBHOOK_INGRESS_DRIVER` applies to **newly registered channels only**. The
  Laravel route always stays live, so switching it does not move channels that
  already exist — use `ops:ingress-migrate` for those. See
  [Webhook gateway](/self-hosting/gateway).
</Note>

## Database

| Variable | Default |
|---|---|
| `DB_CONNECTION` | `pgsql` |
| `DB_HOST` | `127.0.0.1` |
| `DB_PORT` | `5432` |
| `DB_DATABASE` | `fapost_core` |
| `DB_USERNAME` | `root` |
| `DB_PASSWORD` | *empty* |
| `TENANT_DB_CONNECTION` | `pgsql` |
| `LANDLORD_DB_HOST`, `LANDLORD_DB_PORT`, `LANDLORD_DB_DATABASE`, `LANDLORD_DB_USERNAME`, `LANDLORD_DB_PASSWORD` | the matching `DB_*` value (advanced, unsupported for now) |

PostgreSQL is required, not one option among several — landlord and tenant
connections both depend on it. Tenant schemas are created on the tenant connection (`TENANT_DB_CONNECTION`). Do not set the `LANDLORD_DB_*` variables yet: a separate landlord database leaves root tables (cache, jobs, failed jobs, Telescope) where they are not read. The database user needs the `CREATE` privilege; see
[Requirements](/self-hosting/requirements).

## Redis, cache, queues, sessions

| Variable | Default | Notes |
|---|---|---|
| `REDIS_CLIENT` | `phpredis` | |
| `REDIS_HOST` | `127.0.0.1` | |
| `REDIS_PORT` | `6379` | |
| `REDIS_PASSWORD` | `null` | Set one on any non-local install |
| `QUEUE_CONNECTION` | `redis` | Must be an asynchronous queue: on `sync`, `delay` nodes wait for the next inbound message and `send_message` timeouts never fire |
| `CACHE_STORE` | `redis` | |
| `BROADCAST_CONNECTION` | `null` | Live updates of the operator screens (sessions, flow log). `null` or `log` delivers nothing and the screens poll; `reverb` or `pusher` makes the server announce changes on private channels authorized at `/broadcasting/auth`, as jobs on `messaging.system`, and only while a screen is open. See [Realtime](/self-hosting/realtime) |
| `REVERB_APP_ID`, `REVERB_APP_KEY`, `REVERB_APP_SECRET` | *unset* | Shared by the application and Reverb. The key reaches browsers; the secret never does |
| `REVERB_HOST`, `REVERB_PORT`, `REVERB_SCHEME` | *unset* (Compose sets `reverb`, `8080`, `http`) | Where the application publishes events to Reverb |
| `BROADCAST_CLIENT_HOST`, `BROADCAST_CLIENT_PORT`, `BROADCAST_CLIENT_SCHEME` | *unset*: the page's own origin | Where browsers connect, when not the site itself |
| `SESSION_DRIVER` | `redis` | Not `database` in `host` tenancy mode: platform pages have no tenant schema to hold the table |
| `SESSION_LIFETIME` | `120` | Minutes |
| `SESSION_DOMAIN` | *unset* | Leave unset: cookies stay bound to the exact host. In `host` mode a value shared between subdomains is refused |
| `TRUSTED_PROXIES` | *empty* (the Compose file defaults to the address it pins for Caddy, `172.30.0.2`) | Addresses or CIDR ranges allowed to set the client address and scheme through `X-Forwarded-*`, or `*` for whoever connects directly. Empty trusts nobody, so behind a proxy every client shares the proxy's address. The forwarded host and port are never believed. See [the client address behind a proxy](/self-hosting/docker-compose#the-client-address-behind-a-proxy) |

Redis is not optional: it carries queues, cache, locks, and the webhook routing
registry. The registry is what keeps the landlord database off the inbound hot
path — see [Runtime architecture](/contributing/runtime).

## Conversation transcript

| Variable | Default | Notes |
|---|---|---|
| `CONVERSATION_RETENTION_DAYS` | *unset* | Unset keeps the transcript forever. A plain whole number of days (anything else, including `0`, disables pruning) lets `conversations:prune` drop whole monthly `conversation_messages` partitions older than that, so a message lives between that many days and about 31 days longer. **Irreversible**: dropped messages come back only from a database backup. Conversation threads and downloaded media are kept. One value for the whole installation |

See [Conversation retention](/self-hosting/observability#conversation-retention).

## Localisation

| Variable | Default |
|---|---|
| `APP_LOCALE` | `en` |
| `APP_FALLBACK_LOCALE` | `en` |

This is the admin UI language. Content language — what the assistant says to a
contact — is resolved separately at runtime; see
[Multilingual extensions](/extending/multilingual).

## Mail, logging, other

`MAIL_*` follow Laravel's conventions; the default `MAIL_MAILER=log` writes mail to
the log rather than sending it. `LOG_CHANNEL=stack` with `LOG_LEVEL=debug` is the
development default — raise the level in production.

`TELESCOPE_ENABLED` defaults to `true` locally and should be `false` in production.
`HCAPTCHA_SITE_KEY` and `HCAPTCHA_SECRET_KEY` ship with hCaptcha's public test
values, which always pass — replace them before exposing any public form.

<Warning>
  The shipped `.env.example` values for `APP_DEBUG`, `TELESCOPE_ENABLED`, and the
  hCaptcha keys are development defaults. Each is safe locally and unsafe in
  production.
</Warning>
