# 14 — Модели деплоя

> Содержимое зафиксировано на основе platform-architecture-v2. Март 2026.
> 

---

## Три модели

|  | **SaaS (облако)** | **Managed self-hosted** | **Self-hosted** |
| --- | --- | --- | --- |
| **SaaS-оболочка** | ✓ | — | — |
| **Платформа** | ✓ | ✓ (у клиента) | ✓ (у клиента) |
| **Модули** | ✓ | ✓ | ✓ |
| **Обновления** | Авто | Мы деплоим | Клиент: `platform:update` |
| **Manifest validation** | Мы контролируем | Мы контролируем | Phase 1 автоматически |
| **Целевой сегмент** | Средний бизнес | Enterprise (старт) | Enterprise (зрелость) |

---

## SaaS (облако)

Полный стек под управлением команды FaPost. Клиент не управляет инфраструктурой. Обновления автоматические. SaaS-оболочка (тенанты, биллинг, feature flags) работает только здесь.

---

## Managed self-hosted

Платформа разворачивается у клиента, но деплоем управляет команда FaPost. Клиент получает изоляцию данных. SaaS-оболочка отсутствует — биллинг и tenant management вне периметра клиента.

---

## Self-hosted

Клиент управляет инфраструктурой и обновлениями самостоятельно. Единственная точка обновления — `platform:update` (Phase 5, задача 25). Manifest validation и module compatibility check выполняются автоматически в Phase 1 команды.

> ⚠️ Self-hosted — отдельная операционная модель, не просто «то же самое но у клиента». Три проблемы требуют явных решений: Module Manifest & capabilities, platform:update Phase Model, Module Isolated Fail Strategy. Подробнее — в разделе «12 — Self-hosted операционная модель».
>
